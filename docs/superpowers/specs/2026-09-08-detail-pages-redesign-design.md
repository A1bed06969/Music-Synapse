# アーティスト / アルバム / トラック詳細ページ 再設計

## 背景

現行の3つの詳細ページは、情報量と見た目の完成度がばらばらになっている。

- `/artists/[id]`: 2026-08-06の再構築(`2026-08-06-artist-detail-redesign-design.md`)でセクションは揃った。ただし全セクションが同じ文字サイズ・同じ濃さで並び、ヘッダーも小さいため、情報量のわりに平板に見える
- `/albums/[id]`: ジャケット + 3行のメタ情報 + トラックリスト + その他のバージョンのみ。配信リンクも紹介文も無く、構造的に薄い
- `/tracks/[id]`: タイトル + 再生ボタン + 実績セクションのみ。データが少ない曲では画面の2/3が空白になる

あわせて、競合となる音楽データベース [yoyn](https://yoyn.jp/) との差別化も要件に含む。yoynは
**ライトテーマ + 星評価 + ユーザーレビュー**(38,747レビュー / 1,714ユーザー)が主役で、
アルバム・アーティストページとも「左に固定カラム(ジャケ/写真・配信アイコン・基本情報)+ 右にスクロール」という骨格を採る。
本設計はこれと構造・主役の両方をずらす。

## ゴール

- 3ページで共通の「ヘッダー行 → 見開き2段組 → 全幅の棚」というレイアウト規則を持たせ、ページ間の見た目を統一する
- ジャケット/アーティスト写真とタイトルを、どのページでも主役として大きく見せる
- **紹介文・配信/SNSリンク・選出&表彰・ディスコグラフィ**を必ず伝える(ユーザー指定のマスト項目)
- アルバム・トラックページにも紹介文とYouTubeプレーヤーの置き場所を用意する(データが入り次第そのまま表示される形にする)
- テキストデータがほぼ空の現状でも、空白が目立たない見た目にする
- スマホではヘッダーが縮んで上部に固定され、ジャケットとタイトルが常に見える状態を保つ

## 非ゴール(今回やらないこと)

- **クレジットを主役として見せること**。`artist_credit`はアルバム12万件・トラック9万件あるが、表記が煩雑で現状そのまま前面に出せる品質ではない。将来の相関図(アーティスト×クレジットのつながり)の材料として保持する。
  - トラックページには既にクレジット表示が存在するため、**削除はせず`<details>`の折りたたみ(デフォルト閉じ)にして見開きの外(棚の下)へ移す**。データもコードも残るので、品質が整った時点で開いた状態に戻すだけで復帰できる
  - アルバムページには現状クレジット表示が無いため、今回も追加しない
- **星評価・ユーザーレビュー・コレクション等のソーシャル機能**。yoynの主戦場であり、本サイトは選出・表彰とメディア文脈(パワープレイ/フェス/タイアップ)で差別化する
- **紹介文(bio / album_review / track_review)の自動生成**。別課題として切り出す(下記「関連する別課題」参照)
- ライト/ダークのテーマ切り替え。既存のダークテーマを維持する
- 管理画面での紹介文・MV入力フォームの新規作成。既存どおりSupabaseへ直接入力する運用

**この表が本設計の最大の制約**である。文章系のデータは実質存在せず、確実にあるのは
ジャケット画像・タイトル・アーティスト名・収録曲・発売日・配信ID・選出データのみ。
したがって「紹介文が無いときに別のテキストで埋める」設計は成立せず、**図版で埋める**方針を採る。

新規カラムの追加は行わない。紹介文は既存の`album_review` / `track_review` / `artist.bio`、
MVは既存の`track.youtube_video_id` / `artist.url_latest_mv`を使う。
アルバムのMVは、アルバム自身の動画カラムを増やさず`representative_track_id`が指すトラックの
`youtube_video_id`を使う(代表曲が未設定なら1曲目)。

## レイアウト規則(3ページ共通)

```
┌─────────────────────────────────────────────┐
│ ①ヘッダー行                                  │
│  [ジャケ/写真] タイトル・属性・配信/SNSリンク │選出・表彰│
├──────────────────────┬──────────────────────┤
│ ②見開き:左 = 図版スロット │ ②見開き:右 = データ  │
│  紹介文 / MV / 大判アート │  収録曲 / 実績        │
├──────────────────────┴──────────────────────┤
│ ③全幅の棚(ディスコグラフィ・関連作品など)      │
└─────────────────────────────────────────────┘
```

### ①ヘッダー行

- 左からジャケット(または円形のアーティスト写真)、タイトル(最大の文字)、属性の1行(アーティスト名・種別・発売日・レーベル・曲数など中黒区切り)、配信/SNSリンクのボタン列
- 右端に幅の狭い「選出・表彰」カラムを縦線区切りで置く。`ranking_entry` → `ranking`から取得し、既存の`CurationTags`と同じくメディアのファビコン付きバッジで表示する。0件ならカラムごと出さない
- 配信リンクはアイコンのみでなく**名前付きのボタン**(「Apple Music」「Spotify」)にする。yoynは小さい丸アイコンを並べるため、ここで見た目が分かれる

### ②見開き2段組

- 左右の比率は左 `46%` : 右 残り(右をやや広く)。
  当初は「左をやや広く(1.15:1)」としていたが、右カラムが収録曲11行やパワープレイ実績など
  密度の高い内容を持つため、実装時に右を広くする形へ変更した
- 右カラムに何も無いページ(トラックの98.5%が該当)では見開きを解除し、左の図版は
  `max-w-[646px]`で頭打ちにする。解除時に幅の制約が無いと、ジャケットが1552pxの正方形になり
  どの画面よりも縦に長くなるため(最終レビューで検出)
- **左 = 図版スロット**。次の優先順で、最初に存在するものを表示する:
  1. 紹介文(`album_review` / `track_review` / `artist.bio`)
  2. ミュージックビデオ(YouTube埋め込み)
  3. 大判アートワーク(ジャケット/アーティスト写真を正方形で大きく)
  4. 関連ジャケットのモザイク(同じアーティストの他作品を並べる)
  - 1と2は両方あれば両方を縦に積む。3・4は1も2も無いときのフォールバック
- **右 = データ**。ページごとに内容は違うが、いずれも「必ず存在するデータ」を置く(下記ページ別を参照)

### ③全幅の棚

- 既存のディスコグラフィと同じ横スクロールの固定幅カード列を全幅で使う
- 種別ごと(スタジオ/EP/シングル/ライブ等)に見出しを付けて複数行

### レスポンシブ

- **PC(`lg`以上)**: 上記のとおり。ヘッダー行はスクロールしても追従しない(見開きの高さを稼ぐため)
- **スマホ・タブレット(`lg`未満)**: 見開きを解除して1列に積む。順序は「ヘッダー → 左スロットの中身 → 右の中身 → 棚」
- **スマホのヘッダー固定**: ページ最上部のヘッダー行が画面外に出たら、縮小版のバー(小さいジャケット + タイトル + 再生ボタン)を画面上部に固定表示する
  - 実装は`IntersectionObserver`でヘッダー行の可視状態を監視し、非表示になったら固定バーを出すクライアントコンポーネント。既存の`app/components/home/AlbumFocusCarousel.tsx`等と同じ`IntersectionObserver`の使い方に合わせる
  - 固定バーは既存の`SiteHeader`(`sticky top-0 z-20`)の直下に来るよう`top`と`z-index`を合わせる

## ページ別の構成

### アルバム `/albums/[id]`

| 位置 | 内容 | 状態 |
|---|---|---|
| ヘッダー | ジャケット / タイトル / アーティスト・種別・発売日・レーベル・曲数・総時間 / 配信リンク / 選出・表彰 | 配信リンクと選出カラムが新規 |
| 見開き左 | 紹介文 → MV(代表曲の動画) → 大判ジャケット → 関連ジャケのモザイク | 新規 |
| 見開き右 | 収録曲(Disc分割・試聴ボタン付き) | 既存を移設 |
| 棚 | 同じアーティストの他の作品 / その他のバージョン / 掲載ディスクガイド | 「他の作品」が新規 |

配信リンクは`apple_music_album_id` / `spotify_album_id` / `youtube_music_album_id` /
`amazon_music_album_id`と、既存の`tower_url` / `discogs_url`から組み立てる。値が無いものは出さない。

### トラック `/tracks/[id]`

| 位置 | 内容 | 状態 |
|---|---|---|
| ヘッダー | ジャケット(収録アルバム) / タイトル / アーティスト・収録アルバム・再生時間 / 配信リンク・歌詞リンク / 選出・実績 | 配信リンクと選出カラムが新規 |
| 見開き左 | 紹介文 → MV(`youtube_video_id`) → 大判ジャケット | 新規 |
| 見開き右 | パワープレイ/ヘビロテ実績 / タイアップ実績 / 使用楽器 | 既存を移設 |
| 棚 | このアルバムの他の曲 / クレジット(折りたたみ) | 「他の曲」が新規 |

既存の`RotationModal`(パワープレイの3件+モーダル表示)はそのまま右カラムで使う。
クレジットは既存の表示・取得をそのまま残したまま、棚の下に`<details>`で折りたたむ
(デフォルト閉じ、見出しは「クレジット(N件)」)。品質が整えば開いた状態に戻すだけでよい。

### アーティスト `/artists/[id]`

| 位置 | 内容 | 状態 |
|---|---|---|
| ヘッダー | 円形写真 / 名前・読み・英語表記 / 属性(形態・活動年・出身地・配信状況) / 配信・SNSリンク / 選出・表彰 | 既存要素の再配置 |
| 見開き左 | バイオグラフィー → Latest MV → 大判写真 | 再配置 |
| 見開き右 | 代表曲(パワープレイ実績・選出から自動抽出) / ライブ・フェス出演 | 「代表曲」が新規 |
| 棚 | ディスコグラフィ(種別ごと) / 年表 / 相関図プレビュー | 既存を移設 |

配信・SNSリンクは既存の`app/components/ArtistLinkIcons.tsx`をそのまま使う(名前付きボタンの
バリアントを`variant`プロパティで足す)。

「代表曲」は`radio_rotation`(パワープレイ実績)と`ranking_entry`(選出)を持つトラックを
実績件数の多い順に最大5曲。どちらも無いアーティストではセクションごと非表示。

## コンポーネント設計

新規に作る共有コンポーネントは3つだけに絞る。ページ固有の組み立ては各`page.tsx`に置く。

| ファイル | 役割 |
|---|---|
| `app/components/detail/DetailHeader.tsx` | ①ヘッダー行。画像(角丸/円形を切替)・タイトル・属性行・リンク列・選出カラムを受け取るサーバーコンポーネント |
| `app/components/detail/VisualSlot.tsx` | ②見開き左の図版スロット。紹介文/MV/大判画像/モザイクの優先順の分岐をここに閉じ込める |
| `app/components/detail/StickyMiniHeader.tsx` | スマホ用の縮小固定バー。`IntersectionObserver`を使うクライアントコンポーネント |

- 見開きと棚のレイアウトはTailwindのクラスの組み合わせ(`lg:flex lg:gap-8` / `overflow-x-auto`)で足りるため、コンポーネント化しない
- 選出・表彰バッジは既存の`app/components/CurationTags.tsx`をそのまま使う(ファビコン取得は`utils/curationSource.ts`)
- 配信リンクのボタン列は`app/components/detail/ListenLinks.tsx`として最初から共有コンポーネントにする。
  アルバム・トラックの両方が同じ配信サービス(Apple Music / Spotify / YouTube Music / Amazon Music)を
  同じ形で並べるため、2ページで確実に同じものになると分かっているため。アーティストは既存の
  `ArtistLinkIcons`が担当し、こちらとは統合しない(SNSリンクやMusicBrainz由来のリンク種別が別物のため)

## データフロー

1. 各`page.tsx`(サーバーコンポーネント)が既存クエリに加えて以下を取得する
   - アルバム: 配信ID列・`representative_track_id`のトラックの`youtube_video_id`・同アーティストの他作品
   - トラック: 配信ID列・`youtube_video_id`・同アルバムの他の曲
   - アーティスト: 代表曲(`radio_rotation`と`ranking_entry`の集計)
2. `VisualSlot`が受け取った値の有無で左カラムの中身を決める(サーバー側で分岐、クライアントJSは不要)
3. `StickyMiniHeader`のみクライアントで動き、ヘッダー行が画面外に出たら固定バーを表示する

## エラー・空状態

- 紹介文もMVも大判画像も無い(ジャケット未登録の2%) → 関連ジャケのモザイクを出す。関連作品も無ければ**見開きを解除して右カラムを全幅にする**
- 選出・表彰が0件 → ヘッダー右のカラムごと非表示(空の見出しは出さない)
- 配信IDが全て無い → リンク列ごと非表示
- 代表曲・タイアップ・パワープレイが0件 → そのセクションのみ非表示。右カラムが全て空になった場合は見開きを解除して左を全幅にする
- YouTubeのIDが不正で埋め込みURLを作れない → MVセクションを出さない(壊れた埋め込みを出さない。既存のアーティストページと同じ方針)

## テスト方針

自動テストは追加しない(既存の検証スタイルに合わせる)。実装後にPlaywrightで以下を確認する。

1. 紹介文もMVも無いアルバム(大多数)で、左カラムに大判ジャケットが出て空白にならないこと
2. `album_review`を仮に入れたアルバムで、左カラムが紹介文に切り替わること
3. トラックページで、パワープレイ実績のある曲(例: FM802ヘビロテ)の右カラムに実績が出ること
4. 選出のあるアルバム(Rolling Stone 500収録作)のヘッダー右にファビコン付きバッジが出ること
5. スマホ幅(375px)でヘッダーが縮小固定バーに切り替わり、ジャケットとタイトルが常に見えること
6. アーティストページの既存機能(相関図プレビュー・年表・ディスコグラフィ横スクロール)が壊れていないこと
7. `npx tsc --noEmit` と `npx eslint` がクリーンで、`npm run build` が通ること

## 関連する別課題(今回のスコープ外・記録のみ)

**紹介文の自動生成**: `artist.bio`が17,278人中4人、`album_review`が0件という状況のため、
本設計の左スロットは当面ほぼ図版で埋まる。既存のGeminiパイプライン(アーティスト/アルバム
マッチングと同じ`gemini-3.1-flash-lite`)で紹介文を生成する仕組みを別途設計する。

制約として**無料枠(1日500リクエスト)のみを使う**。全件生成は非現実的
(アーティストだけで約35日、アルバム13万件で約9ヶ月)なため、対象を
「選出・表彰のある作品」「パワープレイ実績のある曲」等に絞り込む前提で設計する。

## 実装後に判明した積み残し(別タスク)

- **MemberProfileが旧レイアウトのまま**: `resolveArtistPageKind`がリリースを持たない
  アーティストを`app/artists/[id]/MemberProfile.tsx`へ振り分けており、これは17,321件中
  9,502件(55%)に当たる。本設計は「3ページ」を対象としたためスコープ外としたが、
  バンドページとメンバーページで見た目が揃わない状態が残る。MemberProfileは
  ディスコグラフィを持たない等データ構成が違うため、独自の設計判断が必要
- **細部のスタイル統一**: 棚カードのタイポグラフィが3種類、`h3`のクラス差、
  アーティストページの見出しに英語と日本語が混在、`mt-14`/`mt-10`の揺れ
- **共通化の余地**: 棚カード・アーティスト名のリンク列・選出のdedupe処理が3ページに重複
